## Notes

- Secondary metrics come from the re-score when one exists, otherwise from the value logged at training time. Thresholds are always selected on validation.
- Scoring time is wall-clock per sample on CPU over the whole test pass. For GNNs it includes causal neighbor sampling and node-feature building, so isolated (leak-free) scoring is slower than shared batches. Not end-to-end serving latency.
- GNN neighbor selection is deterministic (most recent k edges before the cutoff), so a sampling seed has no effect and there is no seed-to-seed range to report.
- HeteroGAT 're-scored' values use isolated per-target subgraphs (`isolate_targets=True`): each transaction only sees edges before its own timestamp. The 'shared batches' column scores the same checkpoint with the legacy loader, where all targets in a batch of 2048 share one subgraph and a transaction can see edges sampled for later transactions in the same batch. The checkpoints were trained with the legacy loader. See 'Batch-sharing leak' below.
- GraphSAGE still uses shared batches; its homogeneous loader has no isolated mode.

## Batch-sharing leak

Generated from `data/processed/batch_leak.json` (`scripts/measure_batch_leak.py`). Same rows at every batch size: test = all 813 positives + 20000 random negatives; validation = all 723 positives + 20000 random negatives (seed 42). Batch size 1 = isolated per-target subgraphs; larger sizes = legacy shared batches with the same boundaries as a full ordered pass.

Downsampling negatives raises PR-AUC (precision is computed against fewer negatives), so 'subset PR-AUC' is only comparable across batch sizes. 'Weighted PR-AUC' gives each sampled negative weight 4.99 (all test negatives / sampled), an estimate of full-test PR-AUC. Recall uses a threshold set at 1% FPR on the validation-subset negatives of the same batch size.
